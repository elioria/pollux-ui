# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A fork of BearStudio's start-ui-web v3 (Vite + TanStack Start) being used to port the legacy Pollux Next.js admin. Most of the codebase is generated per-entity CRUD code driven by `json-files/<entity>.json` metadata (originally fetched from `https://dbtool.portalkardec.org.br/api/get-entity-attributes?name=<entity>`).

## Commands

```bash
./pollux help        # Pollux generator CLI (agent-friendly, --json output): list/describe entities,
                     # validate, gen-entity/gen-all/gen-backend, fmt, check, manifest, test, doctor
                     # (see .claude/skills/pollux-cli)
pnpm dev             # dev server (validates env, generates build info, vite dev on :3000)
pnpm build           # production build (Node)
pnpm build:cf        # Cloudflare Workers build (NITRO_PRESET=cloudflare-module); deploy: npx wrangler deploy
pnpm lint            # oxlint --fix + tsc --noEmit (run both via run-p)
pnpm lint:ts         # typecheck only
pnpm format          # oxfmt

pnpm test:ci         # vitest run (headless, what CI runs)
pnpm test:ci src/features/act   # run tests for one path
pnpm test:ci -t "test name"     # run a single test by name
pnpm test            # vitest watch, headless browser

pnpm e2e:setup       # required once before e2e (creates auth context; re-run after DB changes)
pnpm e2e             # playwright headless
pnpm e2e:ui          # playwright UI mode

pnpm dk:init         # first-time Docker (PostgreSQL, MinIO, Maildev)
pnpm dk:start        # start existing containers
pnpm db:init         # db:push + db:seed
pnpm db:push         # drizzle-kit push
pnpm db:ui           # drizzle studio

pnpm storybook       # storybook on :6006
pnpm gen:icons       # regenerate icon components from src/components/icons/svg-sources
```

Unit tests run in real Chromium via vitest browser mode; browser tests match `src/**/*.browser.{test,spec}.*`. Env vars are validated by `src/env/{client,server}.ts` (t3-env); `pnpm dev`/`build` fail fast if they're invalid. Scripts execute TS via `./run-jiti`.

## Architecture

Stack: TanStack Start/Router (file-based routing), oRPC for the API layer, Drizzle ORM on PostgreSQL, Better Auth, Tailwind v4 + shadcn-style components, react-hook-form + zod v4, i18next (`src/locales`). ORM is Drizzle (`drizzle.config.ts`, `src/server/db/schema/`); Prisma was fully removed.

- `src/routes/` — file-based routes; `routeTree.gen.ts` is generated by the router plugin, never edit it.
- `src/server/routers/*.ts` — one oRPC router per entity, aggregated in `src/server/router.ts`. Client access via `src/lib/orpc`.
- `src/server/db/schema/entities/*.ts` — one Drizzle schema file per entity.
- `src/features/<entity>/` — feature verticals: `schema.ts` (zod) + `manager/` (list page, columns, form, new/update pages).
- `src/features/act/` is the hand-built **golden vertical** that generated code mirrors.

### Authorization (role ACL + grant tables)

Two layers, resolved by `src/server/permissions/grant-resolver.ts` (`checkPermissionWithGrants`) and wired into BOTH boundaries — oRPC `protectedProcedure` (`src/server/orpc.ts`) and generated-crud `requireGeneratedPermission`/`getGeneratedCapabilities`:

1. role `admin` → allow (superuser bypass)
2. `perusr.isDenied` for (user, resource) → deny, overrides everything else
3. code-defined better-auth role ACL (`src/features/auth/permissions.ts`, GEN block) → allow
4. `perusr`/`pergrp` grant flags (groups via `usrgrp` membership) → allow
5. otherwise deny

Grants target `res` (resources) rows matched by `res.code === entity name` (UNIQUE constraint, emitted via `UNIQUE_COLUMNS` in `scripts/gen-entity.mjs`); entities without a `res` row are role-ACL only. Flag mapping: `canAdmin` implies all actions, any flag implies `read`, `canInsert/canUpdate/canDelete/canExport` → create/update/delete/export; non-CRUD actions (`list`, `set-role`, `revoke`, ...) are role-ACL only. Duplicate-code rows merge (any `isDenied` denies).

- **Admin UI**: `/manager/admin` (`src/features/admin/`) — overview stats, group/user × resource permission matrix (upserts `pergrp`/`perusr`), group membership manager. Backing router: `src/server/routers/admin.ts`.
- **Client gating**: `account.effectivePermissions` (batched grant map, 4 queries) + `WithPermissions` (`src/features/auth/with-permissions.tsx`) mirror the server precedence, so nav/menu/buttons reflect grants. UI hint only — the server re-checks every call.
- **Go backend parity**: the generated Go service checks permissions through the TS app's grant-aware `POST /api/rest/authz/has-permission` (`src/server/routers/authz.ts`, same `{permissions} -> {success}` contract as better-auth's role-only endpoint) — the resolver stays the single source of truth. Emitted from `_templates/pollux/go-service/auth-client.ejs.t`.
- **Tests**: `pnpm test:ci src/server/permissions` (resolver unit tests); `node scripts/e2e-grants-live.mjs` is a live 18-check suite (needs dev server on :3011 + docker postgres) that creates a real OTP user, seeds random grants, asserts enforcement, and cleans up; `e2e/admin.spec.ts` covers the admin UI; `e2e/go-backend.spec.ts` covers the Go service contract.
- OpenAPI UI for the API at `http://localhost:3000/api/openapi/app`; email previews at `/api/dev/email/<template>`.

### Cloudflare Workers deployment (TypeScript app)

Production target is Cloudflare Workers (one SSR worker + static assets; Pages is maintenance-mode). `pnpm build:cf && npx wrangler deploy`; root `wrangler.jsonc` is merged by Nitro into `.output/server/wrangler.json` (Nitro adds `main`, `assets`, `nodejs_compat`). Full audit, requirements and verification checklist: `docs/operations/cloudflare-workers-deployment.md`.

Database and logging behavior switch at runtime on workerd (detected via
`navigator.userAgent === 'Cloudflare-Workers'`). Email transport selection is
different: it happens at build time so Workers-only `cloudflare:sockets` never
enters the Node bundle and nodemailer's Node TCP dependencies never enter the
Workers bundle.

- `src/server/db/index.ts` — `db` is a lazy Proxy: pooled module-scope client on Node; on workerd one postgres.js client per request (Nitro `useRequest()` + WeakMap, `max: 5`, `fetch_types: false`) because Workers sockets cannot cross requests. Requires `experimental.asyncContext` in `vite.config.ts` (the nitro option's type also demands `vite: {}`).
- `src/server/email.tsx` imports `@/server/email-transport`. Node/dev resolves `email-transport.ts` (nodemailer); `vite.config.ts` aliases the exact import to `email-transport.worker.ts` (worker-mailer over `cloudflare:sockets`, ports 587/465) for `NITRO_PRESET=cloudflare-module`. Both read `EMAIL_SERVER`; `EMAIL_FROM`'s `Name <addr>` form is parsed for worker-mailer.
- `src/server/logger.ts` — pino writes through `console.log` on workerd (sonic-boom fd writes are silently dropped), keeping structured logs in `wrangler tail`.

The Node production bundle needs more than V8's default heap for the full
generated route graph. `pnpm build` sets a 6 GiB build-only heap limit; this
does not affect the production server runtime.

Local smoke: `pnpm dlx wrangler dev --config .output/server/wrangler.json --port 8788` with a `.dev.vars` generated from `.env` — must add `AUTH_ALLOWED_HOSTS`/`VITE_BASE_URL` for the chosen port or Better Auth rejects the host. Production infra still required: Hyperdrive for `DATABASE_URL` (postgres.js ≥ 3.4.5 OK), R2/hosted S3 (MinIO is local-only), SMTP on 587/465 or an HTTP email API, secrets via `wrangler secret put`. The generated Go backend cannot run on Workers.

### Two entity-page generators (do not confuse them)

1. **Native `/manager` generator — `scripts/gen-entity.mjs`**
   Emits a full native CRUD vertical per entity into the modern stack: `src/features/<entity>/`, `src/server/routers/<entity>.ts`, `src/routes/manager/<plural>/`, Drizzle schema, i18n keys, plus nav and router registration. Idempotent; overwrites its own output.
   ```bash
   node scripts/gen-entity.mjs <entity>   # or --all
   ```
   After running: `pnpm db:push && pnpm lint:ts`.

2. **Legacy-style `/generated` pages — hygen templates in `_templates/pollux/` (active; `_templates/pollux-archive/` is the frozen archive)**
   Renders the ported Next.js-style pages into `src/app/(private)/generated/<entity>/` (page, actions, data-table components, dialogs). `src/routes/generated.<entity>.tsx` holds the loader and imports the generated `page.tsx`, which reads data via `getRouteApi('/generated/<entity>')`. Boolean grid columns get a Sim/Não faceted filter in the toolbar. Legacy imports (`next/navigation`, `next/cache`, `@/db/schema`) resolve through `src/shims/` and the `src/db/schema.ts` compat barrel — new entities need their PascalCase row type added to that barrel.
   ```bash
   ./gen-all-go.sh   # renders with gohygen (Go port of hygen, built from sibling ../gohygen checkout, cached in .cache/gohygen)
   ./gen-all.sh      # same output via Node hygen
   ./generate-pollux.sh --backend typescript|go   # explicit backend selector (no default); `go` renders a standalone Gin+Bun+pgx REST service into generated/pollux-go via _templates/pollux/go-{service,entity} (staging + atomic replace; same CrudResult contract + error taxonomy; tests: ./scripts/pollux/test-backend-selection.sh, `cd generated/pollux-go && make test vet`)
   ```
   Both scripts run the `page` + `serverpage` + `form-fields` groups per entity and skip json-files without `data.attributes` (error stubs). They validate metadata first (`scripts/pollux/validate-metadata.mjs`) and abort before writing anything if it fails; `generate-all-entity-pages.sh` is a deprecated alias delegating to `gen-all.sh`.
   All generated server functions run through the shared guarded runtime `src/server/generated-crud/` (`runGeneratedCrud`: Better Auth session + entity/action permission check, zod input validation, error taxonomy, structured logs, transactional `generated_crud_audit` writes). Server functions return a `CrudResult<T>` envelope (`src/lib/generated-crud.ts`) — loaders `unwrapCrudResult`, dialogs branch on `result.ok`. Capability object from the loader (`canCreate/canUpdate/canDelete`) gates UI controls via `src/features/generated-crud/capabilities.tsx`; the server enforces regardless. `pnpm test:ci src/server/generated-crud` runs the authorization matrix + generated-output drift gate — keep it green after any template change.
   After any regen, run the canonical post-gen pipeline — import sort first, formatter LAST (the reverse order is not a fixpoint, and dir-mode oxfmt silently skips some files, so pass explicit file lists):
   ```bash
   pnpm exec oxlint --fix "src/app/(private)/generated" src/routes
   find "src/app/(private)/generated" \( -name '*.ts' -o -name '*.tsx' -o -name '*.css' \) -print0 | xargs -0 pnpm exec oxfmt
   ls src/routes/generated*.tsx | xargs pnpm exec oxfmt
   ```
   `./scripts/pollux/check-drift.sh` runs gen + that pipeline and fails if the result differs from the committed output (needs a clean tree on generated paths). `node scripts/pollux/build-manifest.mjs` regenerates the rollout manifest + inventory under `docs/operations/` — commit both with every regen. Ops docs: `docs/operations/pollux-generated-crud.md` (logs/audit/queries) and `pollux-runbook.md` (rollback, incidents, per-entity disablement).
   Then restart `pnpm dev` if it was running (bulk route rewrites corrupt the vite SSR module graph). To smoke-test generated pages over HTTP, check the SSR response for the TSR hydration payload (`pageCount`, `ssr:!0`) — table markup only renders client-side, so grepping for visible text fails; unauthenticated SSR now returns the app shell with a 500 + structured `UNAUTHENTICATED` warn log, and the client redirects to `/login`.
   The `serverpage` group emits a tablecn-style server-driven variant at `/generated-server/<entity>` (`src/app/(private)/generated/<entity>/serverpage/`): pagination, multi-sort and filters run in SQL (`serverActions.ts` — where/orderBy/limit/offset + count over the same where); URL search params are the single source of truth (`page`, `perPage`, `sort` = JSON `[{"id","desc"}]`, `q`, one param per boolean column); the route loader re-runs on every search change. The server data-table reuses the sibling client components (toolbar, pagination, column header, columns, dialogs) under TanStack `manual*` modes, keeps debounced (300ms) optimistic local mirrors for text/filter inputs, and resets to page 1 on filter changes.
   In generated zod-schema partials, emit code with `<%- %>` (raw) — `<%= %>` HTML-escapes quotes into `&#39;`.

### Multi-skeleton standalone targets (SPEC-001..007, experimental)

Besides the two in-repo generators, `skeletons/` holds copyable app boilerplates (`nextjs`, `remix`, `astro`, `tanstack-start`; `start-ui-vite` = this repo, reference-only) that Pollux can generate standalone CRUD frontends into over the external `/api/generated/v2` contract. All four standalone targets are **experimental** (`generatorSupport.pollux: false`) — promotion waits on the Go v2 backend + PKCE/BFF auth plus a green CI matrix. Support matrix + contracts: `skeletons/README.md`; ops: `docs/operations/pollux-skeletons-runbook.md`.

```bash
./pollux new-workspace <skeleton> --dir=<path>       # staged + atomic copy, provenance in .pollux/workspace.json
./pollux plan|generate --workspace=<path> --entity=<e> [--all]   # journaled, all-or-nothing; version gates reject before writes
./pollux check-generated --workspace=<path>          # ownership drift + pending journals
node scripts/pollux/test/workspace-matrix.mjs --target nextjs|remix|astro|tanstack-start   # SPEC-007 full gate: create → generate rich-valid →
    # pnpm install --frozen-lockfile → typecheck/test/build (offline) → no-source-dependency scan → mock v2 API + app runtime smoke
node scripts/pollux/test/no-source-dependency.mjs --workspace <path>        # generated workspace never imports this checkout
node --test scripts/pollux/test/version-compat.unit.spec.mjs                # provenance/model/adapter mismatches fail pre-write
```

Adapters live in `scripts/pollux/targets/{nextjs,react-router,astro-react,tanstack-start}/` (templates: `_templates/pollux-targets/`), the normalized entity model in `scripts/pollux/model/`, golden fixtures in `test-fixtures/pollux/golden/<target>/`, the mock v2 API in `test-fixtures/pollux/api/mock-server.mjs` (`amostra` entity from `test-fixtures/pollux/entities/rich-valid.json`). CI (`code-quality.yml`): `pollux-unit` (node --test suites incl. contract + adapters), `pollux-matrix` (nextjs/remix/astro/tanstack-start legs), `pollux-matrix-gate` (fails if any leg fails or is skipped).

Entity names are short codes (`act`, `aut`, `pesq`, `lechis`, ...). Route dirs under `src/routes/manager/` use a simple plural: append `s`, or `es` if the name already ends in `s`.

### Cross-model plugin package (`plugins/pollux-ui/`)

`plugins/pollux-ui/` packages Pollux templates, layouts, design tokens, and verification workflows for Codex and Claude as one neutral plugin (`pollux.plugin.json`) with two generated host projections (`.codex-plugin/`, `.claude-plugin/`) and five shared skills under `skills/`. Specs: `docs/specs/ai-plugins/`; design: `docs/superpowers/specs/2026-08-11-pollux-cross-model-plugin-design.md`. Canonical sources stay in this repo; `plugins/pollux-ui/resources/` is a generated, hash-addressed snapshot — never hand-edit it, rebuild it.

```bash
node plugins/pollux-ui/scripts/build-manifest.mjs       # neutral manifest (deterministic digest)
node plugins/pollux-ui/scripts/build-resources.mjs      # resource snapshot + resources/catalog.json
node plugins/pollux-ui/scripts/build-projections.mjs    # .codex-plugin + .claude-plugin + agents/openai.yaml
node plugins/pollux-ui/scripts/validate-package.mjs     # full package validation
node plugins/pollux-ui/scripts/verify-source-drift.mjs  # snapshot-vs-source drift gate
node plugins/pollux-ui/scripts/validate-hosts.mjs       # current Codex + Claude validators, warnings fail
node plugins/pollux-ui/scripts/evaluate-triggers.mjs --host=codex|claudeCode
node plugins/pollux-ui/scripts/evaluate-workflows.mjs --host=codex|claudeCode
node plugins/pollux-ui/scripts/build-release.mjs        # release.json + dist tarball (needs clean canonical sources)
node --test "plugins/pollux-ui/tests/*.unit.spec.mjs"   # package test suite
```

After changing anything under `_templates/pollux*`, `skeletons/`, `src/layout/`, or the packaged references, re-run the chain above (`pnpm pollux:plugin`) — stale snapshots fail `verify-source-drift` with the exact resource ID.
Model evaluation runners use repo-owned fresh-session adapters; missing hosts
or authentication are failures, never skips. The 2026-08-11 matrices passed
17/17 triggers and 9/9 artifact workflows in both Codex 0.147.0 and Claude Code
2.1.220, promoting the repo-local package to Stage 4 (cross-model

## Conventions

- Import order is enforced (simple-import-sort via oxlint); generated code sorts imports to pass lint on first pass.
- React Compiler (babel-plugin-react-compiler) is active. Components that read mutable TanStack Table v8 state (`table.getState()`, `column.getFilterValue()`, ...) must start with `'use no memo'` or the compiler memoizes them into stale UI — the generated data-table templates already do this.
- Toasts: sonner mounted via `src/components/ui/sonner.tsx` — `bottom-right`, `richColors` (green/red/amber/blue), `closeButton`. Never set a background/text class on `toastOptions.classNames.toast`; it overrides richColors back to monochrome. The `next/navigation` shim's `router.refresh()` maps to TanStack `router.invalidate()` (in-place loader refetch) — not `location.reload()`, which would wipe in-flight toasts and page state.
- `src/components/ui/dropdown-menu.tsx` is **Base UI**, not Radix, despite shadcn-style names. Differences that bite templates ported from Radix: `DropdownMenuLabel` = `Menu.GroupLabel` and throws unless wrapped in `DropdownMenuGroup`; keep-open-on-click is `closeOnClick={false}` on items, not `onSelect={(e) => e.preventDefault()}`. Same family of gotchas applies to other Base UI wrappers (`asChild` is mapped via `src/lib/as-child.ts`).
- Lefthook runs git hooks (installed on `pnpm install`).
- UI language for Pollux pages is Portuguese.
