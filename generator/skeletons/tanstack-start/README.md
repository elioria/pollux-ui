# Pollux skeleton — TanStack Start (React + Vite)

Copyable boilerplate for a standalone Pollux CRUD frontend on TanStack Start
(React 19 + Vite + file-based routing, Node server output via Nitro). Created
through `./pollux new-workspace tanstack-start --dir=<path>`; entity pages are
generated by the `tanstack-start` target adapter (SPEC-008) over the external
`/api/generated/v2` contract.

## Commands

```bash
pnpm dev          # vite dev server
pnpm build        # production build (.output/)
pnpm start        # node .output/server/index.mjs (honors PORT)
pnpm typecheck    # tsr generate && tsc --noEmit (canonical order)
pnpm test         # node --test test/skeleton.test.mjs (fresh-skeleton invariants)
```

## Layout hooks for generated code

- Routing is file-based: generated pages land under
  `src/routes/manager/<plural>/` and the framework's route-tree generator
  (`tsr generate` / the Start vite plugin) picks them up — no handwritten
  route registry to edit.
- `src/routes/__root.tsx` (handwritten) collects sidebar fragments from
  `src/generated/pollux/nav/*.ts` via `import.meta.glob`.
- The same-origin proxy and BFF auth endpoints are generated at
  `src/routes/api/pollux/$.ts` and `src/routes/api/pollux/auth.$action.ts`;
  shared runtime/UI land under `src/lib/pollux/` and `src/components/pollux/`.
- `src/routeTree.gen.ts` is framework-generated (committed fresh; regenerated
  by `pnpm typecheck`/`dev`/`build` after generation). Never edit it.

## Environment (server-only)

See `.env.example`. `POLLUX_API_URL` + optional `POLLUX_DEV_BEARER` enable the
DEV-ONLY proxy mode; the five `POLLUX_AUTH_*`/`POLLUX_SESSION_SECRET`/
`POLLUX_PUBLIC_ORIGIN` variables enable the PKCE/BFF cookie flow. No variable
may ever gain a `VITE_` prefix — they are read via `process.env` inside server
modules only.

## Known limitations (EXPERIMENTAL)

- SSR data fetch authenticates only in dev-bearer mode: the HttpOnly access
  cookie is path-scoped to `/api/pollux` and browser-held, and SSR loaders
  reach the proxy over a loopback self-fetch (`POLLUX_PUBLIC_ORIGIN` or
  `http://127.0.0.1:$PORT`), so cookie-mode sessions render client-side.
- Rate limiting is delegated to the deployment platform.
- `generate --all` over several entities is unsupported on standalone targets
  (shared-file ownership) — generate entities one at a time.
