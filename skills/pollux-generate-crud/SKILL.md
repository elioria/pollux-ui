# pollux-generate-crud

Regenerate Pollux output through the canonical `./pollux` CLI only. Never
call hygen/gohygen or the shell scripts directly, and never hand-edit
generated files — change metadata or templates, then regenerate.

## Preconditions

- Inspect first (see `pollux-inspect`): know the generator surface, the
  entity names, dirty paths, and target support status.
- Metadata validates before any write: `./pollux validate [entity...]`.
- Backend/target selection is explicit. If the user did not say which
  surface, ask one bounded question; there are no silent defaults.
- Generated paths must be clean. `--accept-generated-overwrite` is never
  inferred — require explicit user approval after naming the exact
  generator-owned files.

## Surfaces and canonical commands

**Legacy TypeScript `/generated` + `/generated-server`**
(`_templates/pollux/{page,serverpage,form-fields}`):

```bash
./pollux validate                      # fail fast on bad metadata
./pollux gen-entity <entity>           # or: ./pollux gen-all
./pollux fmt                           # REQUIRED: oxlint --fix, then oxfmt
./pollux test --suite=unit
./pollux check                         # byte-identical regeneration proof
```

Commit generated output together with the template/metadata change, then
`./pollux manifest` and commit the refreshed manifest.

**Standalone Go backend** (`_templates/pollux/{go-service,go-entity}`):

```bash
./pollux gen-backend --backend=go      # validate → staging → tidy → gofmt → atomic replace
./pollux test --suite=go
./pollux test --suite=selection
```

**Standalone framework targets** (`nextjs`, `react-router`/remix, `astro`, `tanstack-start`;
all experimental — keep the label visible):

```bash
./pollux plan --workspace=<path> --entity=<name> --json   # dry-run, no writes
./pollux generate --workspace=<path> --entity=<name>      # journaled, all-or-nothing
./pollux check-generated --workspace=<path>               # ownership gate
```

## Steps

1. Run the read-only inspection and record dirty paths; preserve unrelated
   dirty work — never stash, reset, checkout, or format it.
2. Validate metadata; on failure report diagnostics and stop
   (`PLAN_INVALID`). Stubs (`audit_log`, `objcss`) are always skipped.
3. Execute the canonical command for the selected surface. For standalone
   targets, run `plan` first and show the affected paths.
4. Run the surface's verification gates (above). For standalone targets also
   run the matching workspace matrix when generation changed:
   `node scripts/pollux/test/workspace-matrix.mjs --target <nextjs|remix|astro|tanstack-start>`.
5. Report evidence: entities processed, changed paths (from the CLI output or
   `git status --porcelain` filtered to generator-owned paths), commands run,
   and unresolved gaps.

## Gotchas the CLI already encodes (do not work around)

- `./pollux fmt` order is load-bearing: oxfmt-then-oxlint is not a fixpoint.
- `./pollux check` requires clean generated paths — commit or stash first.
- After a bulk regeneration, restart `pnpm dev` (route rewrites corrupt the
  Vite SSR module graph).
- Entity names are the short codes from `json-files/*.json`
  (`fortestsonly` is the synthetic all-types entity). If the requested
  entity has no metadata file yet, switch to the pollux-author-entity
  skill to author + validate it first — never hand-write generated code
  to compensate.
- Native `/manager` verticals are generated by `scripts/gen-entity.mjs`
  feature code, not by `_templates/pollux` — do not run template groups
  against them.

## Failure behavior

- `GENERATED_EDITED` / `OWNERSHIP_CONFLICT` → stop; name the files; resolve
  through regeneration or explicit user-approved overwrite only.
- `TARGET_UNSUPPORTED` / `TARGET_MISMATCH` → stop; report the skeleton's
  `generatorSupport` notes verbatim.
- Dirty generated paths required by a drift gate → `GENERATED_PATH_DIRTY`,
  stop; ask the user to commit or stash those specific paths.
